    Managing Single Sign-On (SSO)

    Configure SAML-based Single Sign-On (SSO) for your organization.
    This allows users to authenticate through your Identity Provider (IdP), such as Azure AD, Google Workspace, or Okta.

    Overview

    The Manage Single Sign-On page allows administrators to enable or disable SSO, provide IdP metadata, map groups to organization roles, and define access control rules for user authentication.

    Example Image: Manage SSO Configuration Page

    Enabling SSO

    1. Toggle Enable SSO at the top of the page.
    2. When enabled, users will be able to sign in using your configured Identity Provider.
    3. If disabled, only local Cloudpie user accounts can log in.

    Providing IdP Metadata

    You can configure your SAML IdP in two ways:

    Option 1 – Metadata URL (Recommended)

    • Enter your IdP’s Metadata URL in the IdP Metadata URL field.
    • Cloudpie automatically fetches and parses the metadata, retrieving:
    • IdP Entity ID
    • SSO and SLO URLs
    • X.509 Certificate

    Example: 

    https://login.microsoftonline.com/<tenant-id>/federationmetadata/2007-06/federationmetadata.xml

    Option 2 – Manual Configuration

    If metadata URL parsing is not possible, manually enter: - IdP Entity ID - IdP SSO URL - IdP SLO URL (optional) - IdP Certificate (X.509)

    Default Roles for New SSO Users

    • This setting defines which organization roles will be assigned to new users when they first log in using SSO.
    • Example roles: org_viewer, org_editor, org_admin.
    • Leave this field empty to create users without default roles.

    Note:
    Roles assigned here only apply to users created via auto-provisioning.
    Existing users retain their current roles unless overwritten by group mapping.

    Auto-Provisioning Users

    When Auto-provision new users is enabled: - A new user is automatically created in Cloudpie upon their first SSO login. - Default roles (if configured) are applied.

    When disabled: - Only users who already exist in Cloudpie can sign in using SSO. - No new user accounts are created automatically.

    Access Control

    Choose who can access your organization via SSO:

    1. Open – Allow all users from your IdP.
    2. Email Domain – Restrict access to specific email domains.
    3. Group Whitelist – Allow only users belonging to approved SAML groups.

    Attribute Mapping

    Cloudpie requires information from your SAML assertion to map user identity and group membership.

    • Email Attribute
      Default: email
      The SAML attribute used as the user’s email identifier.

    • Groups Attribute (Optional)
      Default: groups
      The attribute listing the groups or roles a user belongs to in your IdP.

    Group Mapping

    You can map SAML groups from your IdP to Cloudpie organization roles.

    1. Enable Group Mapping.
    2. Enter one or more mappings:
    3. SAML Group Name → Cloudpie Role

    4. Example: Engineering → org_editor

    5. You can add multiple mappings using the Add Mapping button.

    Behavior:
    - When a user logs in, their SAML group memberships are checked.
    - If a mapping exists, the corresponding Cloudpie roles are assigned or updated.
    - Group mappings always overwrite default roles for that login.

    Service Provider (SP) Metadata

    Your organization’s SP metadata allows your IdP to establish trust.

    Use the provided URLs:

    • Metadata URL: 

      https://<your-subdomain>.cloudpie.io/api/v1/sso/metadata

    • Assertion Consumer Service (ACS) URL: 

      https://<your-subdomain>.cloudpie.io/api/v1/sso/acs

    Provide these URLs to your Identity Provider when configuring the SAML trust.

    Actions

    The following actions are available at the bottom of the page:

    • Save Configuration – Save or update the current SSO setup.
    • Reset Form – Revert any unsaved changes.
    • Check Status – Validate your current SSO configuration.
    • Re-parse Metadata – Re-fetch and re-parse metadata from the IdP.
    • Test SSO Login – Perform a test login to verify SSO setup.
    • Delete Config – Permanently remove all SSO configuration data.

    Notes and Best Practices

    • Always verify your IdP metadata URL is accessible and up to date.
    • When changing certificates or URLs, re-parse metadata to refresh Cloudpie’s configuration.
    • Group Mapping (if enabled) takes precedence over Default Roles.
    • If Auto-Provision is disabled, ensure users are manually added in advance.
    • Keep at least one local admin account accessible for emergency login (non-SSO).
